# Bato Update — Nepal road status (v3)

**Is the road open?** A mobile-first installable web app (PWA) that shows the
latest road status for **every national highway of Nepal (NH01–NH80)** —
per highway and per segment: **Open / One-way / Partial / Closed / Unknown**,
with what a traveler will actually face on the way, when it was last confirmed,
the source, and alternative routes.

Live at: `https://daveyadav.github.io/weatherapp/` (GitHub Pages must be
enabled on the repo: Settings → Pages → Deploy from branch → `main` → `/ (root)`)

## How it works

- **Highway data** (`data/corridors.json`, generated by `/tmp/gen_corridors.py`)
  — 80 corridors (79 NH refs from the authoritative DoR NAVIGATE road list,
  fetched 2026-10-07, + the Pharping–Kulekhani–Bhimphedi alternative), 265
  places, 141 named chokepoint segments. Seed statuses are UNKNOWN — the live
  feed fills them at runtime. Statuses older than 24h are displayed grey as
  *possibly outdated*, never a confident green.
- **Travel notes** — 22 corridors carry researched travel intelligence
  (landslide chokepoints, night rules, vehicle limits, monsoon behaviour,
  known hazards) grounded in 2026-10-07 news research; the rest are openly
  marked unverified and rely on the live feed.
- **Live feed** (`js/navigate.js`) — pulls the Department of Roads NAVIGATE
  closure feed (`GET https://navigate.dor.gov.np/api/Map_data_api/getRoadClosureMapData`,
  verified live 2026-10-07, no auth). Records are matched to corridors by
  `road_refno` (dynamic map built from the corridor list) with name fallback.
  For covered corridors, a segment with no closure record = OPEN, stamped with
  the feed fetch time. Refetch at most every 15 minutes; last good payload kept
  in `localStorage` for offline use. If the fetch fails (network/CORS), the app
  falls back to seed data and shows "live feed unreachable".
- **Trip planner** — a route graph over corridor endpoints lets From → To span
  multiple corridors (e.g. Kathmandu → Nepalgunj). Results render as a
  **journey timeline**: every segment as a colored node with "what to expect"
  there, so the traveler sees the whole journey's story.
- **Offline** — service worker (`bato-update-v2` cache) caches the shell +
  corridor data; an "Offline — showing last-known data" banner appears when
  the device is offline.
- **Version footer** (`v2 • 2026-10-07`) — diagnoses stale phone caches.

## Data sources

1. DoR NAVIGATE (navigate.dor.gov.np) — official per-section closures, live feed
2. Nepal Traffic Police — holds, releases, one-way rulings
3. News (Rising Nepal Daily, OnlineKhabar, Khabarhub, The Himalayan Times,
   Ratopati, Hamro Patro…) — backup + travel-note research
4. DHM weather — risk context only, never shown as a closure (v3)

## Updating statuses

- Automatic: the NAVIGATE live feed refreshes segments on every app open
  (throttled to 15 min).
- Manual: edit `data/corridors.json` (one entry per segment: `status`, `cause`,
  `note`, `updated_at` ISO with +05:45, `source_name`, `source_url`) and push —
  or re-run `/tmp/gen_corridors.py` after editing its spec. Bump `APP_VERSION`
  in `js/app.js`, the footer in `index.html`, and the service-worker `CACHE`
  name in `sw.js` so phones pick up the new build.

## Tech

Vanilla HTML/CSS/JS, no frameworks. PWA: `manifest.json` + `sw.js`.
No backend — static hosting on GitHub Pages.
